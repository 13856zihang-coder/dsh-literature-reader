# 文献阅读室 / Literature Reader

一个用于 DSH Web GUI 的本地文献阅读插件。文献库与 Obsidian vault `D:\note` 的文件夹结构同构；导入的 PDF 会保存到当前 Obsidian 文件夹，已有的 PDF 会自动同步进库。阅读时可以框选截图提问、用可调粗细的画笔做批注，并按章节提炼要点。读完后一键生成带标签的 Markdown 学习总结，写入 Obsidian 并自动打开。

## 功能

- **导入即通读**：自动提取 PDF 正文、识别章节结构，生成可供后续答疑使用的深度阅读备忘。
- **扫描版 OCR**：正文文字过少时，自动逐页调用当前视觉模型 OCR；支持断点续跑。
- **可调阅读布局**：PDF 与 AI 对话之间可左右拖动分栏；默认约 74/26，可拖到接近 80/20，双击恢复默认。
- **PDF 缩放**：阅读器底部用 −/+ 在 40%–300% 之间缩放；按住 Ctrl（macOS 为 ⌘）滚动鼠标滚轮可无级缩放，并以鼠标所在位置为中心；点击中间的百分比数字立即回到 100%。
- **拖动阅读**：工具栏新增“拖动”工具；选中后按住鼠标左键即可像抓住纸张一样平移文档，放大后也能从容查看局部；松开后恢复，框选、画笔等工具不受影响。
- **全屏阅读**：阅读工具条右侧的全屏按钮让阅读器占满整个屏幕（浏览器原生全屏，自动收起 DSH 侧边栏、隐藏插件顶部标题栏和 Windows 任务栏），按 Esc 或再点一次退出；全屏时保留阅读工具条、PDF、右侧 AI 对话，以及天气小组件和壁纸插件的背景，退出后分栏宽度与侧边栏状态都会恢复。
- **清爽的阅读界面**：以纸张暖色和单一强调色为基调，工具栏、阅读摘要与快捷提问按功能着色；解析文献时显示平滑渐变进度条与状态光点，不再用旋转加载图标打断阅读。
- **框选提问**：在页面上拖出矩形，自动生成截图交给 AI；支持翻译、解释、名词解释、提炼要点、质疑等快捷按钮。
- **自选模型与思考强度**：聊天面板右上角的模型胶囊可直接切换模型服务和模型，并在同一处调整思考强度（跟随模型 / off / low / medium / high / xhigh / max，按模型实际支持的档位显示）。选择只作用于文献阅读室，保存在插件数据目录，不会改动 DSH 的默认模型；不支持图片输入的模型会标注“不支持图片”，因为它们无法做扫描版 OCR 与框选截图答疑。
- **可调阅读字号**：输入框右下角的 `−  100%  +` 可在 70%–220% 之间调整右侧问答区与输入框的字号，点击百分比恢复 100%；设置会记住。
- **按框选内容决定回答长度**：框选只是一个单词或短语时，“翻译”只给中文释义和一句语境义；框选是一句话或一段话时，只给结合上下文的中文译文，不额外解释、总结或点评。需要展开讲解时再点“解释”。
- **英文单词自动归档**：用“翻译”处理单词或短语后，自动在该文献的 `[[链接]]` 下追加一条编号记录（`单词 → 翻译`）到你 Obsidian 的“英文单词”笔记。已收录的单词/短语不会重复写入，而是弹出提醒告诉你在第几条；写入前会在插件备份目录保留笔记副本。
- **画笔批注**：黄/红/蓝/黑四色，画笔和橡皮的粗细都可调，批注按页保存。
- **章节提炼**：自动识别章节，也可以自定义页范围，点击“提炼”生成章节要点。
- **阅读笔记**：阅读室下方的记录面板里直接写 Markdown（工具条 + Obsidian 一致的快捷键、公式与图片预览），按 `Ctrl/Cmd+Enter` 追加成一条带时间戳的记录，写入 PDF 旁边的 `<PDF 名> 笔记.md`；面板展开时 PDF 与 AI 对话一起缩小让出空间，不遮挡正在读的内容；窄屏自动变成整页编辑。
- **整理笔记**：用当前模型整理整篇笔记。格式美化、错别字、重复合并直接写回正文（写前留快照），疑似错误只列清单、逐条确认后再决定改不改，可先与 AI 讨论。
- **学习总结**：结合全文、AI 理解备忘与本次问答记录，生成一份**用于快速回顾的速览**（不是学习笔记）：速览、这篇文献讲了什么、核心方法 / 技术点、关键结论、论文未解决的问题、已弄懂的知识点、名词解释，写入 Obsidian。局限与前提判断不单独立节，融入正文叙述。核心方法一节按文献技术内核的实际复杂度决定详略，不设字数标准；篇幅由文献内容决定，约束的是「不注水」。单词翻译记录不会混进总结，但翻译过的专业名词会收进文末的「名词解释」；通过与 AI 问答彻底搞懂的内容会以陈述句知识点收录，不会罗列成一串问题。
- **总结视图**：总结生成后进入全屏视图。选中任意一段文字即可在浮动工具条里写下标注（4 种颜色），可以连续标注多处；**标注不会自动改动正文**，只有点下方的「应用修改」，AI 才逐条按标注修订，只替换被标注的片段，并回报每条标注的处理结果（已应用 / 未能应用 / 已失效）。
- **手动编辑 Markdown**：总结支持像编辑文档一样直接改源码并保存（`Ctrl/Cmd+S`），带冲突检测（409 时可选覆盖或重新载入）、离开确认与本地草稿恢复；每次保存前自动留存历史版本，可预览与一键恢复。
- **自动插图**：生成总结时，AI 会在确实有图表且对理解有价值的地方插入图片占位符，插件用视觉模型定位、从 PDF 中精确裁剪并保存到 Obsidian 的 `_附件/<文献>/图/`；单张定位失败会用提示块代替，不影响正文。
- **手动插图与位置提问**：也可以自己插入图片（本地上传，或从 PDF 页面框选截取），并说明放在哪里。如果没有说位置，AI 会主动提问确认后再插入，不会擅自决定。
- **Obsidian 同构文献库**：全屏文献库直接镜像 `D:\note` 的目录结构，分为“文献 PDF”和“阅读笔记”两个视图；在 Obsidian 中新增/移动 PDF 后会自动出现。文献 PDF 视图里一篇文献占一行，可展开看到它的速览总结与阅读笔记（不存在则显示“尚未生成”），点一下就直接打开；笔记视图默认只列不属于任何文献的独立笔记，顶部开关可切回全量平铺。
- **文献库管理**：PDF 和笔记卡片可以直接拖到左侧文件夹；文件夹支持重命名和删除；文献、笔记、文件夹都可以删除，删除前会二次确认并列出关联笔记可选一并删除；被删除的内容会先移入插件备份目录，误删可找回。删除文献时可以选只删记录、连同速览总结、或连同速览总结与阅读笔记一起删（后两者先移入备份目录）。
- **名称与标签联动**：在文献库中编辑标题、PDF 文件名和标签。修改文件名会重命名实际 PDF，并自动更新 vault 内可识别的 `[[链接]]`；默认勾选“同时重命名关联笔记”时，关联笔记也会一起改名（自定义名会保留“笔记”等后缀），取消勾选则保留笔记原名、只更新链接和 frontmatter。标题和标签写入关联笔记 frontmatter。

## 阅读笔记怎么用

「一篇文章 = 三件套」：PDF、速览总结、阅读笔记放在同一个文件夹、互相链接、一起搬。

### 记录一条笔记

1. 打开一篇文献，点右上角的 **建立笔记**（第一次；**全屏时按钮在 PDF 顶部工具栏的「提炼」右边**）——插件在 PDF 旁边建好 `<PDF 名> 笔记.md`，随即展开记录面板，按钮也变成 **记录笔记**。
2. 之后每次点 **记录笔记** 都会展开同一个面板。它是布局里的一块，不是浮层：PDF 与右侧 AI 对话同时缩小让出空间，正在读的页面不会被盖住；拖动面板上边缘可调高度（160px–60vh），高度会记住。
3. 写 Markdown，按 `Ctrl/Cmd+Enter` 或点 **记录**，内容作为一条新记录追加进笔记，面板自动收起并提示「已记录到笔记」。
4. 想直接改整篇笔记：点旁边的 **修改笔记**（笔形图标）在 Obsidian 里打开。

面板里工具条从左到右：加粗 / 斜体 / 链接 / 三级标题 / 无序 / 有序 / 引用 / 行内代码 / 行内公式 / 块公式 / 插入图片 / 字号 − % + / 编辑·预览 / 快捷键帮助（`?`）。每个按钮的悬浮提示都写着对应快捷键。预览用同一套 Markdown 与公式渲染，`$$\frac{a}{b}$$` 这类公式直接显示出来；粘贴剪贴板里的图片会自动上传并插入链接。编辑区内容按文献存本地草稿（防抖 400ms），提交成功后清空；下次打开若非空会自动恢复，关面板时有内容会二次确认。

### 快捷键（编辑区内生效，macOS 上 `Cmd` 等价 `Ctrl`）

| 动作 | 快捷键 | 动作 | 快捷键 |
| --- | --- | --- | --- |
| 加粗 | `Ctrl+B` | 行内公式 | `Ctrl+M` |
| 斜体 | `Ctrl+I` | 块公式 | `Ctrl+Shift+M` |
| 链接 | `Ctrl+K` | 插入图片 | `Ctrl+Shift+I` |
| 一级 / 二级 / 三级标题 | `Ctrl+1` / `2` / `3` | 字号 + / − / 复位 | `Ctrl+=` / `Ctrl+-` / `Ctrl+Shift+0` |
| 恢复正文（去行首标记） | `Ctrl+0` | 记录 | `Ctrl/Cmd+Enter` |
| 无序 / 有序列表 | `Ctrl+Shift+8` / `Ctrl+Shift+7` | 关闭面板 | `Esc` |
| 引用 | `Ctrl+Shift+Q` | 行内代码 | `` Ctrl+Shift+` `` |

Tab 缩进两个空格，其余按键保持文本域原生的行为。

### 记录的格式

每条记录是一个二级标题加正文，按天分组：

```markdown
# 2026-11-07

## 21:03 · 第一条记录的正文开头…

正文照原样保留你写的 Markdown。

## 21:41 · 第二条记录
```

标题里的时间取本地时区 24 小时制（分钟补零），` · ` 后面是**你输入的第一行文字**。
第一行超过 30 个字时，标题只显示前 30 个字加 `…`，**但完整的一行会原样留在正文里**，不会丢字。
所以写法是：**先写一行标题，回车，再写正文**——第一行会变成条目标题并从正文里移除，不会被重复一遍；
只写一行就记录，那就是「只有标题、没有正文」的条目。取不到文字（比如整条只有一张图）时只留 `## 21:03`。旧格式 `## 21:03 记录` 仍被识别与计数，已存在的旧标题不会被改写。同一分钟内多条记录允许重复标题。笔记开头的 frontmatter 里有 `paper_id`、`pdf`、`summary_note`，配合正文顶部的关联提示块实现与 PDF、速览总结的双向链接。

### 整理笔记与疑似错误

工具栏「整理笔记」（AI 阅读助手标题行，笔记存在时才出现）会用**当前选中的模型**一次性整理整篇笔记，不做二次确认弹窗；角标数字是尚未处理的疑似错误条数。

- **直接写回正文**：格式美化、错别字、重复合并。写之前先把整份文件存进历史快照，随时能还原。
- **只列清单、不动正文**：疑似错误。判定尺度是保守的，只报四类硬错误——数字/年份/引用与原文对不上、因果关系说反、术语用错、结论与前提矛盾；措辞风格、能不能合并、够不够学术一律不提。
- 每条疑似错误显示原文片段、问题说明与要问你的问题。你可以补充一句话让 **与 AI 讨论** 流式聊清楚，也可以 **在 AI 对话中继续讨论**（把片段和疑问作为一条消息交给右侧助手），再选 **按讨论结果修正**（只替换被确认的那一小段）或 **保留原文**。没处理的会一直保持待确认状态：待确认条数显示在「记录笔记」与「整理笔记」按钮的角标上。**下次点「记录笔记」打开面板时，待确认的条目会直接列出来**（不必重跑一次整理，也不会因此消耗模型调用）；点「整理笔记」则会连同新发现一起重新列出，讨论过的话都在。
- 整理结果会先过一道安全闸：如果改写会破坏结构（比如丢了标题、链接、代码块、frontmatter、时间戳，或大幅删减原文），整次整理直接放弃、提示原因、不落盘也不产生疑似错误。

### 历史与还原

记录面板顶栏的 **历史** 按钮打开历史抽屉，最新在前，每条显示时间、字数与来源（记录 / 整理 / 修正 / 恢复 / 手动保存）。点开是只读预览（同样的 Markdown 与公式渲染），**恢复此版本** 会二次确认，并先把当前正文也存成一份快照——恢复本身也可以再撤回。每篇文献各存 30 份。

### 笔记文件被删掉了怎么办

如果在 Obsidian 里把 `笔记.md` 删了，下次点按钮时插件会先说「原笔记文件已丢失（路径），要重新建立吗？」。历史快照仍然在，可以从 **历史** 里把内容找回来，不必重写。

### 窄屏

窗口宽度 ≤860px 时，记录面板不再是下方面板，而是占满插件面板的整页编辑器，顶栏保留「关闭」「记录」，写作与预览整页切换。

### 删除文献时

弹窗里三选一：**只删记录**（Obsidian 里三件套全留）、**连同速览总结**、**连同总结与笔记**（还会删 `_附件/<paperId>/`）。后两者都先移入插件备份目录 `backups/delete-*`，可以找回。

## 数据位置

默认配置在 `cordis.patch.yml`：

- PDF 原件：保存在 Obsidian vault 中，通常是当前选中的文件夹，例如 `D:\note\文献\<文件名>.pdf`。
- 文献处理缓存：`D:\DSH-Literature`
  - `papers/<id>/pages/*.jpg`（页面图）
  - `papers/<id>/text.json`（逐页正文/OCR）
  - `papers/<id>/analysis.md`（AI 深度阅读备忘）
  - `papers/<id>/chat.json`（问答与章节提炼记录）
  - `papers/<id>/annotations.json`（画笔批注）
  - `papers/<id>/summary.md`（本地总结副本）
  - `papers/<id>/summary-annotations.json`（学习笔记上的标注；未点“应用修改”前一直保留）
  - `papers/<id>/summary-history/*.md`（每次保存前的正文快照，最多保留 30 份）
  - `papers/<id>/reader-note-history/<stamp>.md`（阅读笔记每次写入前的完整文件快照，最多保留 30 份，同目录 `.json` 记录来源）
  - `papers/<id>/reader-note-questions.json`（“整理笔记”发现的疑似错误与逐条讨论记录）
  - `papers/<id>/figures/*.png`（学习笔记与阅读笔记里的图片本地副本）
  - `papers/<id>/meta.json`（标题、标签、状态、vault 相对路径）
  - `assets/<sha2>/<sha256>.pdf`（旧版内容寻址 PDF；仅用于兼容历史导入）
  - `backups/rename-*`（重命名或修改 frontmatter 前的 Markdown 备份）
  - `backups/delete-*`（删除文献、笔记或文件夹前的备份，可手动找回）
  - `backups/word-note/*`（追加英文单词记录前的笔记副本）
- **三件套（一篇文章的三个文件放在同一个文件夹，互相链接）**：PDF 在哪个文件夹，速览总结与阅读笔记就在哪个文件夹，文件名取 PDF 文件名去扩展名（`meta.fileName` 缺失时依次退到标题、id）：
  - 文献：`D:\note\serdes\接收端\a.pdf`
  - 速览总结：`D:\note\serdes\接收端\a 总结.md`（在此之前生成的旧总结如果还在 `文献阅读\<标题> (<年份>).md`，继续原地更新，不强制改名或搬家）
  - 阅读笔记：`D:\note\serdes\接收端\a 笔记.md`（唯一权威；正文里 `[[a.pdf]]`、`[[a 总结]]` 与总结里的反向链接互相指认）
  - PDF 不在 vault 内（本地导入、尚未归入文件夹）时，两者退到 `notesFolder`（默认 `文献阅读`）。
  - 在文献库里重命名或移动 PDF 时，总结、笔记与附件目录跟着一起改/一起搬；单独移动笔记或总结不影响 PDF。
- 关联笔记按 frontmatter 的 `pdf`/`title`/`tags` 读写。阅读笔记写 `note_role: "reader-note"`、速览总结写 `note_role: "summary"`，因此文献库“笔记”一栏始终指向速览总结，不会被阅读笔记抢走。
- 图片分两个子目录，互不干扰：速览总结的图在 `D:\note\serdes\接收端\_附件\<paperId>\图\`，阅读笔记的图在 `D:\note\serdes\接收端\_附件\<paperId>\笔记\`；正文分别以 `_附件/<paperId>/图/<文件名>.png`、`_附件/<paperId>/笔记/<文件名>.png` 相对链接引用，在 Obsidian 中可直接显示。旧链接 `_附件/<paperId>/<文件名>.png` 保持有效，不迁移、不改写。
- 英文单词笔记：`D:\note\英文单词.md`（可用 `wordNote` 配置改名）。笔记内每个 `[[文献链接]]` 段落下列出该文献记录过的单词，格式为 `序号.单词或短语 → 中文翻译`；插件只追加新条目，不改写已有内容。

页面图、OCR 文本和缓存都在非 C 盘目录。OCR 时会临时使用 DSH 的图片附件存储（由宿主管理的规范化缓存）。

## 与“学习工作台”的关系

学习工作台的资料管理方案以 Obsidian 仓库内的原文件和正文为权威，SQLite 只管理属性、标签与关联；当前版本没有可调用的外部 HTTP API，也没有已落地的 Obsidian 写入能力。因此本插件采用**文件层配合**，不写入学习工作台的 SQLite 或个人数据库，也不改变它的项目方向：

- PDF 直接存放在 Obsidian vault，和 Obsidian 文件夹完全一致。
- 笔记是普通 Markdown，frontmatter 保留 `title`、`authors`、`year`、`venue`、`doi`、`tags`、`paper_id`、`source_app`、`source_pdf`、`source_path`、`vault_path`、`source_sha256`、`source_original_name` 等字段，方便学习工作台未来把笔记作为普通资料登记。
- 如果以后要做“在插件里读取学习工作台已有文献目录”，建议让学习工作台新增一个**只读导出 IPC**，而不是由插件直接连它的数据库。

## 配置

可选配置项（写在安装包的 `cordis.patch.yml` 中）：

```yaml
config:
  dataDir: 'D:/DSH-Literature'
  obsidianVault: 'D:/note'
  notesFolder: '文献阅读'
  wordNote: '英文单词'     # 记录翻译过的单词/短语的 Obsidian 笔记名
  importFolder: ''        # 默认导入文件夹；留空则用文献库当前选中的文件夹
  autoOpenObsidian: true
  provider: ''            # 留空则跟随面板里的选择或 DSH 当前默认模型
  model: ''               # 留空则跟随面板里的选择或 DSH 当前默认模型
  reasoningEffort: ''     # 留空则跟随模型自己的默认档位；面板里保存过的选择优先于此项
  maxSummaryFigures: 5     # 学习总结最多自动截取几张图；0 表示关闭自动插图
  popplerDir: ''          # 留空自动查找 pdftoppm
```

`notesFolder`（默认 `文献阅读`）在本轮之后只作**回退目录**：文献在 vault 内时，速览总结与阅读笔记都写在 PDF 所在的文件夹（三件套同目录）；只有文献不在 vault 内（本地导入、尚未归入文件夹）时才退到这里，`_附件` 也跟着退。

## 依赖

- Poppler（`pdftoppm`、`pdftotext`、`pdfinfo`）。本机已安装时会自动从 PATH 或 WinGet 目录找到。
- 当前默认模型需要支持图片输入，才能对扫描版做 OCR 和框选截图答疑。
- 自动插图（从 PDF 截取图片）同样需要支持图片输入的模型来定位图在页面上的位置。模型不支持图片时，总结仍会生成，只是图位置会改用提示块显示，正文不受影响。
- 阅读笔记与「整理笔记」只处理文本，不需要视觉能力；「整理笔记」用当前选中的模型，整理期间与总结生成互斥。

```bash
node --test                    # 全部单测与集成测试（当前 405 例 / 38 套件，全绿）
node --check index.js client.js
```

阅读笔记相关的测试分布在 `test/reader-note.test.mjs`（纯逻辑）、`test/reader-note-ai.test.mjs`（提示词与解析）、
`test/reader-note-api.test.mjs`（路由）、`test/tripod.test.mjs`（三件套联动）、`test/reader-note-ui.test.mjs`（客户端纯函数与组件树）与
`test/reader-note-integration.test.mjs`（端到端：建三件套 → 记录 → 图片 → 整理 → 讨论 → 修正 → 改名/移动 → 删除）。
契约文档是 `docs/reader-note-spec.md`，覆盖矩阵见 `docs/qa-coverage.md`。

真实链路验证脚本（需要 DSH 正在运行，且会调用模型）：

```bash
node scripts/live-check.mjs <paperId>            # 只读检查，不改任何数据
node scripts/live-check.mjs <paperId> --apply    # 真实生成一次学习笔记
node scripts/live-revise.mjs <paperId>           # 标注 → 应用修改 → 历史恢复
```

`scripts/live-revise.mjs` 默认在结束时清除验证用的标注并把笔记恢复到生成时的版本，加 `--keep` 可保留中间结果。

改动 Host 层（`index.js`、`lib/*.js`）后需要重启 DSH 才会生效；只改 `client.js` 时刷新页面即可。
