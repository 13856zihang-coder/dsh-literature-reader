# 文献阅读室 / Literature Reader

一个用于 DSH Web GUI 的本地文献阅读插件。文献库与 Obsidian vault `D:\note` 的文件夹结构同构；导入的 PDF 会保存到当前 Obsidian 文件夹，已有的 PDF 会自动同步进库。阅读时可以框选截图提问、用可调粗细的画笔做批注，并按章节提炼要点。读完后一键生成带标签的 Markdown 学习总结，写入 Obsidian 并自动打开。

## 功能

- **导入即通读**：自动提取 PDF 正文、识别章节结构，生成可供后续答疑使用的深度阅读备忘。
- **扫描版 OCR**：正文文字过少时，自动逐页调用当前视觉模型 OCR；支持断点续跑。
- **可调阅读布局**：PDF 与 AI 对话之间可左右拖动分栏；默认约 74/26，可拖到接近 80/20，双击恢复默认。
- **PDF 缩放**：阅读器底部用 −/+ 在 40%–300% 之间缩放；按住 Ctrl（macOS 为 ⌘）滚动鼠标滚轮可无级缩放，并以鼠标所在位置为中心；点击中间的百分比数字立即回到 100%。
- **拖动阅读**：工具栏新增“拖动”工具；选中后按住鼠标左键即可像抓住纸张一样平移文档，放大后也能从容查看局部；松开后恢复，框选、画笔等工具不受影响。
- **清爽的阅读界面**：以纸张暖色和单一强调色为基调，工具栏、阅读摘要与快捷提问按功能着色；解析文献时显示平滑渐变进度条与状态光点，不再用旋转加载图标打断阅读。
- **框选提问**：在页面上拖出矩形，自动生成截图交给 AI；支持翻译、解释、名词解释、提炼要点、质疑等快捷按钮。
- **自选模型与思考强度**：聊天面板右上角的模型胶囊可直接切换模型服务和模型，并在同一处调整思考强度（跟随模型 / off / low / medium / high / xhigh / max，按模型实际支持的档位显示）。选择只作用于文献阅读室，保存在插件数据目录，不会改动 DSH 的默认模型；不支持图片输入的模型会标注“不支持图片”，因为它们无法做扫描版 OCR 与框选截图答疑。
- **可调阅读字号**：输入框右下角的 `−  100%  +` 可在 70%–220% 之间调整右侧问答区与输入框的字号，点击百分比恢复 100%；设置会记住。
- **按框选内容决定回答长度**：框选只是一个单词或短语时，“翻译”只给中文释义和一句语境义；框选是一句话或一段话时，只给结合上下文的中文译文，不额外解释、总结或点评。需要展开讲解时再点“解释”。
- **英文单词自动归档**：用“翻译”处理单词或短语后，自动在该文献的 `[[链接]]` 下追加一条编号记录（`单词 → 翻译`）到你 Obsidian 的“英文单词”笔记。已收录的单词/短语不会重复写入，而是弹出提醒告诉你在第几条；写入前会在插件备份目录保留笔记副本。
- **画笔批注**：黄/红/蓝/黑四色，画笔和橡皮的粗细都可调，批注按页保存。
- **章节提炼**：自动识别章节，也可以自定义页范围，点击“提炼”生成章节要点。
- **学习总结**：结合全文、AI 理解备忘与本次问答记录，生成可复习的总结报告和标签，写入 Obsidian。
- **Obsidian 同构文献库**：全屏文献库直接镜像 `D:\note` 的目录结构，分为“文献 PDF”和“阅读笔记”两个视图；在 Obsidian 中新增/移动 PDF 后会自动出现。
- **文献库管理**：PDF 和笔记卡片可以直接拖到左侧文件夹；文件夹支持重命名和删除；文献、笔记、文件夹都可以删除，删除前会二次确认并列出关联笔记可选一并删除；被删除的内容会先移入插件备份目录，误删可找回。
- **名称与标签联动**：在文献库中编辑标题、PDF 文件名和标签。修改文件名会重命名实际 PDF，并自动更新 vault 内可识别的 `[[链接]]`；默认勾选“同时重命名关联笔记”时，关联笔记也会一起改名（自定义名会保留“笔记”等后缀），取消勾选则保留笔记原名、只更新链接和 frontmatter。标题和标签写入关联笔记 frontmatter。

## 数据位置

默认配置在 `cordis.patch.yml`：

- PDF 原件：保存在 Obsidian vault 中，通常是当前选中的文件夹，例如 `D:\note\文献\<文件名>.pdf`。
- 文献处理缓存：`D:\DSH-Literature`
  - `papers/<id>/pages/*.jpg`（页面图）
  - `papers/<id>/text.json`（逐页正文/OCR）
  - `papers/<id>/analysis.md`（AI 深度阅读备忘）
  - `papers/<id>/chat.json`（问答与章节提炼记录）
  - `papers/<id>/annotations.json`（画笔批注）
  - `papers/<id>/summary.md`（本地总结副本）
  - `papers/<id>/meta.json`（标题、标签、状态、vault 相对路径）
  - `assets/<sha2>/<sha256>.pdf`（旧版内容寻址 PDF；仅用于兼容历史导入）
  - `backups/rename-*`（重命名或修改 frontmatter 前的 Markdown 备份）
  - `backups/delete-*`（删除文献、笔记或文件夹前的备份，可手动找回）
  - `backups/word-note/*`（追加英文单词记录前的笔记副本）
- Obsidian 笔记：`D:\note\文献阅读\<标题> (<年份>).md`；关联笔记按 frontmatter 的 `pdf`/`title`/`tags` 读写。
- 英文单词笔记：`D:\note\英文单词.md`（可用 `wordNote` 配置改名）。笔记内每个 `[[文献链接]]` 段落下列出该文献记录过的单词，格式为 `序号.单词或短语 → 中文翻译`；插件只追加新条目，不改写已有内容。

页面图、OCR 文本和缓存都在非 C 盘目录。OCR 时会临时使用 DSH 的图片附件存储（由宿主管理的规范化缓存）。

## 与“学习工作台”的关系

学习工作台的资料管理方案以 Obsidian 仓库内的原文件和正文为权威，SQLite 只管理属性、标签与关联；当前版本没有可调用的外部 HTTP API，也没有已落地的 Obsidian 写入能力。因此本插件采用**文件层配合**，不写入学习工作台的 SQLite 或个人数据库，也不改变它的项目方向：

- PDF 直接存放在 Obsidian vault，和 Obsidian 文件夹完全一致。
- 笔记是普通 Markdown，frontmatter 保留 `title`、`authors`、`year`、`venue`、`doi`、`tags`、`paper_id`、`source_app`、`source_pdf`、`source_path`、`vault_path`、`source_sha256`、`source_original_name` 等字段，方便学习工作台未来把笔记作为普通资料登记。
- 如果以后要做“在插件里读取学习工作台已有文献目录”，建议让学习工作台新增一个**只读导出 IPC**，而不是由插件直接连它的数据库。

## 配置

可选配置项（写在安装包的 `cordis.patch.yml` 中）：

```yaml
config:
  dataDir: 'D:/DSH-Literature'
  obsidianVault: 'D:/note'
  notesFolder: '文献阅读'
  wordNote: '英文单词'     # 记录翻译过的单词/短语的 Obsidian 笔记名
  importFolder: ''        # 默认导入文件夹；留空则用文献库当前选中的文件夹
  autoOpenObsidian: true
  provider: ''            # 留空则跟随面板里的选择或 DSH 当前默认模型
  model: ''               # 留空则跟随面板里的选择或 DSH 当前默认模型
  reasoningEffort: ''     # 留空则跟随模型自己的默认档位；面板里保存过的选择优先于此项
  popplerDir: ''          # 留空自动查找 pdftoppm
```

## 依赖

- Poppler（`pdftoppm`、`pdftotext`、`pdfinfo`）。本机已安装时会自动从 PATH 或 WinGet 目录找到。
- 当前默认模型需要支持图片输入，才能对扫描版做 OCR 和框选截图答疑。
