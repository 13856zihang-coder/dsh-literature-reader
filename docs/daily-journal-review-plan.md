# DSH「每日记录与回顾」插件实施计划书

版本：2026-11-09，Asia/Shanghai。状态：DRAFT，待用户审查；本文件不代表产品实现或使用验收通过。

建议插件：`@local/dsh-review`；独立目录：`F:\dsh\dsh-review`；HTTP 前缀：`/dsh-review`；侧栏名称：每日记录与回顾。

本计划暂存于文献阅读室的 docs，实施对象是独立插件。文献管理按用户说明作为已完成的集成基线，本轮不重新改造文献库，不迁移学习工作台业务数据。

## 1. 用户目标与本轮决定

### 1.1 最新用户原话

> 纠正一下，现在请你帮我再写一个计划，刚才的文献管理工具已经完成了，接下来的计划是将每日记录与回顾在dsh中实现，现在请你仔细勘察学习工作台的工作文档，计划文档，改造文档，帮我写一份计划书出来，markdown格式。注意每日的总结只需要简单记录，每周、每月的才需要有系统性的结构完善，规划清晰的记录和建议等等。这个插件的功能要和其他的插件配合起来。

本轮另行确认：周/月回顾的 AI 生成，**直接使用 DSH 已配置模型**。原工作台方案的“导出给 Codex、再手工导回”不作为首版必需流程。

### 1.2 一句话定位

每天用几句话记下值得留下的事情，任务、专注、运动和阅读事实自动引用；每周、每月再据此形成有出处、有重点、有明确后续行动的回顾。

三个层次保持不同复杂度：

| 层次 | 用户需要做什么 | 插件产出 | 默认是否调用 AI |
|---|---|---|---|
| 每日 | 写一两句或几条简记，可关联任务或文献 | 日期、简记、所选引用；已有事实折叠显示 | 否 |
| 每周 | 选择自然周，检查来源和私人范围，生成并审阅 | 成果、进展、问题、变化和下周行动计划 | 用户点击后调用 |
| 每月 | 选择自然月，检查本月事实和允许参考的历史 | 阶段成果、趋势、目标偏差、经验及下月重点 | 用户点击后调用 |

不要求每日填写结构化长报告、打分、多个必填分类或每日 AI 总结。每日空白代表未记录，不代表没有学习、没有运动或没有努力。

不能直接把待办 `/api/review` 当作四插件的唯一事实来源：

1. 它没有日记、文献、明细 ID 和来源可用状态。
2. 它通过同目录 sibling JSON 读取专注与训练；各插件可独立设置 dataDir，目录不同会漏读，失败又可能表现为零。
3. 其专注口径包含未取消的会话，使用 floor；专注插件正式统计仅计已完成 focus，使用 round。
4. `range=month` 是近 30 天，不是自然月；新插件必须计算首末日并明确传参。

当前各插件可以打开对应面板，但未核得按日期和记录 ID 定位高亮的完整协议。精确“回到原记录”需要列入配套改造，不能只用跳到面板冒充完成。

## 3. 首版范围与插件分工

### 3.1 本插件负责

- 每日简记、按日期补记、草稿、保存冲突和历史恢复。
- 四来源事实的只读聚合、可用状态、出处、去重和明确统计口径。
- 自然周/月选择、输入预览、DSH 模型调用、候选审阅、确认存档和历史比较。
- 来源快照、报告版本、来源变化提示、取消及失败恢复。
- 从报告查看原始证据，并跳回对应插件的记录。

### 3.2 其他插件继续负责

| 插件 | 保持的职责 | 本次允许的最小配套改动 |
|---|---|---|
| dsh-todo | 任务、目标、完成状态、顺延和原复盘 | 增加只读回顾来源接口；接收任务/日期定位；可选“记入今日简记”入口 |
| dsh-focus | 计时、音频、会话和原统计 | 增加不推进计时的只读来源接口；按 sessionId 定位 |
| dsh-training | 计划、训练记录、照片和原统计 | 增加只读计划/记录来源接口；按 recordId 和日期定位；默认不返回照片 |
| literature-reader | 文献管理、解析、阅读、笔记和归档 | 增加只读阅读事实投影及定位；可选“关联到今日简记”；不重做资料管理 |

来源插件的数据仍由来源插件维护。新插件不直接读写它们的 JSON 文件，不复制一套可编辑任务/训练，不要求它们使用同一 dataDir，不自动完成任务或修改运动计划。

### 3.3 本阶段不做

知识图谱、研究发现、完整项目/实验管理、独立长文编辑器、旧工作台数据库迁移、日历同步、系统通知、自动定时生成、自动修改待办/训练、独立模型或凭据系统。天气、壁纸、音频仍由已有插件提供，不成为回顾依赖。

工作/实验进展先通过每日简记表达；未来有项目插件后，再按来源协议接入，不为本阶段先建立空项目平台。

## 4. 每日记录：默认一块简记区

### 4.1 页面与流程

进入默认今天，可切换日期或从月历选日。主区只有“今日简记”编辑框：用户写几句话、列表或简短 Markdown，即可保存。不设每日固定报告章节、强制字数和情绪分数。

示例只作输入引导，不作为必填模板：

```text
今天弄清了均衡器论文里的反馈路径，补了两段笔记。
实验还卡在误码率不稳定，明天先检查测量条件。
跑步后状态不错。
```

旁边或下方折叠显示“已有记录”：完成的任务、已完成专注、训练、明确读完/回顾的文献。用户不必重复填写里程、时长和任务标题。

支持搜索并关联任务、文献或笔记；关联只保存稳定引用，不触发 PDF 解析、不改原记录。快捷入口带来的内容先成为可编辑草稿，不自动保存或标记源任务完成。

### 4.2 可选内容与保存

- 可选“明天想先做什么”，仅是简短备忘，不自动创建待办。
- 可选折叠“私密补充”，与普通简记分开存储，默认不进入 AI 输入，也不自动写入共享 Markdown 目录。
- 普通简记默认使用用户确认的记录目录，建议为当前 Obsidian 仓库的 `工作台记录/日记`；不硬编码 `D:\note`。
- 首次设置确认目录和内容范围，此后不每次保存重复询问。未配置、离线或无权限时保留本地草稿，明确显示未存档。
- 草稿按日期和实体隔离，编辑防抖落草稿；点击保存或 Ctrl/Cmd+S 才报业务保存成功。
- 切日、切面板和关闭前等待当前保存或保留草稿；失败不能清空编辑区。日期改变不改变原记录的事实日期。
- 补记支持过去日期；createdAt/updatedAt 与 occurredOn 分开。补记使尚未确认的相关回顾快照过期，不自动改写已确认报告。

自动事实栏是当前视图；日记保存时可保留当时所选引用与必要只读证据快照。快照不能在新插件中变成可独立修改的任务/训练数据。

## 5. 周回顾与月回顾的结构

### 5.1 周回顾

默认自然周：Asia/Shanghai，周一至周日；当前周标明“截至某日某时”。先查看覆盖天数、来源状态、缺记和本次选中内容，再生成候选。

| 报告部分 | 必须回答的问题 | 约束 |
|---|---|---|
| 本周概览 | 本周最值得记住的 3–5 件事是什么？ | 有对应出处，不按字数凑满 |
| 学习与阅读 | 弄懂了什么、读完/回顾了什么、留下哪些笔记和问题？ | 打开文献不算读完，标签或 mtime 不代表学习成果 |
| 工作与实验 | 实际推进了什么、什么未完成、哪些问题尚待验证？ | 未记录原因就写未知，不替用户编实验结论 |
| 计划与执行 | 原计划、实际完成、延期和当前目标状态有何区别？ | 计划完成率与实际完成数量分开 |
| 专注、运动与状态 | 已记录的投入和节奏如何，主观状态有哪些明确记录？ | 不以专注时长判断学习质量，不把 null/缺记录当 0 |
| 问题与变化 | 相比允许参考的历史，哪些改善或反复出现？ | 事实、推断、待确认问题分开 |
| 下周行动 | 下一周最值得做的 3–5 个动作是什么？ | 按优先级给最小动作、完成标准、建议时机及依据，不自动排程 |

每条建议需包含：做什么、依据/原因、第一步、完成标准、建议时间或顺序。避免“继续努力、提高效率”等无法执行的空话。未知投入时间可以不填，不编造成已承诺计划。

### 5.2 月回顾

使用自然月首日至末日，与近 30 天分开。月回顾读取本月原始事实、每日简记和允许参考的已确认报告；周报是背景，不替代原始来源，也不能与原始事实相加重复计数。

月报结构：

1. 本月主题与关键成果。
2. 学习、工作/实验、生活状态和运动的阶段性回顾。
3. 目标推进、延后事项及原因中“已知/待确认”的区分。
4. 周与周之间的变化、稳定习惯、反复出现的问题。
5. 与允许参考的已确认上月报告比较，说明天数、来源覆盖和统计口径差异。
6. 本月值得保留的经验与应调整的做法。
7. 下月 3–5 个重点及分阶段行动：优先级、首周动作、检查点、完成标准。

未结束月份不称为完整月报；完整月与半月不直接给“明显退步”等结论。当前没有项目结构化来源时，可以总结日记中的工作进展，但不能显示伪造的项目完成百分比。

### 5.3 没有足够资料时

完全没有可用来源时不调用模型补故事。展示空状态并允许保存空白回顾草稿。部分缺失时仍可生成，但报告必须列明覆盖范围和缺口，只评价有证据的部分。

## 6. 跨插件来源与统计合同

### 6.1 来源接口

四插件各增加版本化、严格只读的 `GET <现有前缀>/api/review-source?from=YYYY-MM-DD&to=YYYY-MM-DD`，并按自己的真实配置读取数据；文献插件为 `GET /literature-reader/api/review-source`。

这是一组拟新增接口，当前不能当作已存在。保留原接口和既有统计，不以新回顾为名改旧统计口径。

响应至少包含：`schema`、`provider`、`scopeId`、`range`、`observedAt`、`capabilities`、`coverage`、`records`、`totals`、分页信息与警告。每条记录有来源类型、稳定 ID、业务日期、时间精度、必要事实、定位信息，以及实际可提供的版本依据。

- `coverage` 区分完整、部分历史、最新状态、未安装/未接入、能力不支持、读取失败、已接入但无记录。失败或未知不得变成零。
- 分页使用绑定同一只读快照的 cursor，给出总量或明确的完整标志。原接口的 500/1000 条上限不能导致无提示漏读。
- 获取所有页后、发送模型前及采用报告前重新校验本次输入；来源改变或快照失效须重新预览，不拼接不同版本分页。
- 若来源没有原生 revision，不用 mtime 冒充内容版本；由适配器保留精确规范化事实快照与校验令牌。令牌失效时重新读取，不据旧令牌强行确认。
- 专注来源接口只投影已有会话状态，不调用会推进 current 的方法；训练来源不调用会补齐计划的 getWeek。照片、音频、附件字节、凭据不进入默认来源响应。
- 各来源独立超时与错误。一个插件缺失不阻止写简记或基于其他来源回顾；失败后不能无限重试。

新插件通过固定同源路径的服务端来源适配器读取，不接受客户端指定任意 URL、文件路径或请求头。实现前核对 DSH 本机路由和认证方式；不能通过不受约束的地址转发引入跨站读取。没有可用源接口时显示未接入，不偷偷改读 sibling 文件。

### 6.2 统一统计口径

| 事实 | 本插件采用的规则 | 不允许的推断 |
|---|---|---|
| 普通任务实际完成 | 有真实 completedAt 的当前完成记录按该时刻转换为 Asia/Shanghai 日期；延期任务即使 targetDate 在期外也必须能被来源接口返回 | 不能只按 targetDate 查询后声称拿到了全部实际完成任务 |
| 计划完成率 | 沿用 Todo 计划日/历史快照定义，单独标注“按计划日，截至快照时刻” | 不与实际完成数量混称同一指标 |
| 重复任务 | 使用 recurId@date 稳定身份和已确认的发生日期；合成 completedAt 标为精确时刻未知 | 不用合成午夜时间分析工作时段 |
| 删除/撤销后的旧任务 | 优先展示已保存日记或已确认报告的只读证据；无足够历史则标覆盖不完整 | 不从剩余任务或 recordedAt 反造完整完成时间线 |
| 正式专注统计 | 只累计 completed 且 mode=focus 的 actualSeconds；在计算层合计秒数，展示时统一转分钟，与 Focus 口径核对 | 不把休息、运行中会话当作已完成专注 |
| 中断专注 | cancelled 中已落盘的实际秒数可单列“中断但已投入”，不混入已完成专注 | 不把取消记录实际投入当成 0，也不擅改 Focus 原统计 |
| 跨午夜专注 | 兼容会话开始日 date 归属，显示起止时刻及跨日提示 | 不伪造逐日分摊后的精确 actualSeconds |
| 训练 | 按用户记录的业务 date；里程/时长/爬升分别累计已知值，并给缺项数量 | 缺训练记录不等于休息；null 不等于真实 0 |
| 阅读与笔记 | 使用 catalogId/paperId、显式 readAt/reviewedAt 和人工引用；原文缺失仍保留已有引用 | 打开、解析、归档、文件 mtime 均不等于阅读成果 |
| 阅读历史范围 | 当前最近时间字段按 latest_only 展示；日记保存的明确引用可保留当时证据 | 不把最近一次回顾时间推成完整历史事件流 |
| 目标 | 当前目标状态作为截至本次快照的状态；变化需有实际历史依据 | 仅凭 updatedAt 不宣称本周完成了某个里程碑 |

按 `provider + scopeId + entityId/occurrenceId` 去重；来源事件与当前状态分开。日记、来源记录和历史周报引用同一任务时不能重复计数。

旧数据没有时区/完成时间时保留原业务日期及精度说明；不默认为新规则下的精确历史。统计由代码计算，AI 负责组织和解释，不负责重新算数。

### 6.3 原记录定位与快捷关联

新增最小导航协议，使用当前已存在的 `ctx.layout.selectPanel` 打开目标面板。导航消息带版本、requestId、provider、scopeId、entityId 和业务日期；文献来源另外带 catalogId/paperId。

目标插件全局入口接收并验证消息，面板挂载后选择日期、记录并高亮，返回已定位/缺失/不支持的回执。不能依赖固定延时或覆盖旧 localStorage 选择来假装定位成功。

源记录已删除时仍可看回顾保存的证据快照，并显示“原记录当前不可用”。没有实现定位的插件只能显示“打开对应插件”，不能标成“已定位原记录”。

“记入今日简记”只传稳定引用和必要标题；用户可以选择记录日期，先落草稿再确认保存，不把动作误记成任务完成或阅读完成。

## 7. DSH 模型生成与隐私

首版使用 DSH 已配置 provider/model，插件可以从宿主模型列表选择文本模型；不新增 API key、endpoint、向量库或模型运行环境。模型选择属于本插件配置，不自动改其他插件选择。

完整流程：

```text
选自然周/月与截至时间
  → 检查来源可用性、数据覆盖和缺记
  → 选择本次使用的记录、字段及已确认历史
  → 预览实际将发送的内容和模型
  → 确认并冻结输入快照
  → 调用 DSH 模型，显示进度，可取消
  → 校验候选结构、范围和引用
  → 用户修改、核对出处
  → 确认采用，保存新报告修订
```

- 默认包括选中期间的普通简记、必要事实和用户确认的文献属性/理解摘要；不默认读取整本笔记、PDF 全文、聊天历史或照片。
- 私密补充、心情/健康等独立私人字段默认排除。每次预览可看见本次具体选择；已经声明 restricted/local_only 的来源不能被“全选”覆盖。
- 当前四插件尚未核得统一隐私合同，适配器必须明确新增的字段级选择与能力，不能声称已经继承不存在的保护。
- 简记正文可能含私人内容，发送预览必须展示实际文本并允许排除整条或节选；不宣称系统能自动识别全部敏感内容。
- 历史背景默认仅建议上一份同类已确认报告，可由用户取消或增选；只读保全原文须与确认版本匹配，外部修改后的文件不能冒用旧 confirmed 身份。
- 输入中的日记、笔记和模型输出均作为不可信资料，不能触发工具执行、读其他文件、改变系统指令或扩大来源范围。
- 超过当前模型上下文时展示超限范围，用户可减少选择；也可显式采用分批整理。分批中间产物不是已确认报告，保留完整来源清单，不静默丢记录。
- 输出要求分开事实、变化、问题/不确定项、建议及来源 ID。未知引用、越期记录或结构错误拒绝直接采用；自动校验只能证明结构和引用身份，语义支撑仍由用户审阅。
- 取消先持久化终态，随后中止请求、丢弃迟到 delta/DONE；同一输入重试复用请求身份，重新生成建立新修订，不覆盖已确认报告。
- 建议只展示。首版不自动写待办、改目标或调整训练；用户可复制行动建议，再到对应插件自主安排。

## 8. 数据与保存设计

### 8.1 唯一权威

| 数据 | 权威位置 | 说明 |
|---|---|---|
| 原任务、会话、训练、文献状态 | 各来源插件 | 新插件仅只读消费，不依赖同目录假设 |
| 普通每日简记 | 用户确认目录内的 Markdown | 新插件与 Obsidian 共享同一正文，不能双向维护两份可编辑正文 |
| 私密补充和未存档草稿 | 新插件独立数据目录 | 默认不进入共享目录及模型输入；本地存储不代表加密 |
| 快照、来源索引、候选、采用状态与操作收据 | 新插件版本化 JSON/只读快照文件 | 必须备份，不称为全可丢弃缓存 |
| 已确认周/月正文 | 记录目录中的对应 Markdown 修订 | 保存确认时的只读原文及来源快照，外部改动作为新修订重新确认 |

新插件数据目录建议独立为 `$DSH_HOME/study-workbench/review`，可配置；不得写入 todo.json、focus.json、training.json 或文献 catalog.json。

共享 Markdown 推荐目录：当前已确认仓库下的 `工作台记录/日记`、`工作台记录/周报`、`工作台记录/月报`。首次配置时确认真实根和范围，不根据旧文档直接读写 `D:\note`。本计划阶段不创建这些业务目录。

文件名建议日记 `YYYY-MM-DD.md`；周报 `YYYY-MM-DD_YYYY-MM-DD-rN.md`；月报 `YYYY-MM-rN.md`。使用稳定 journalId/reportId 关联，不把路径当永久身份；已有文件按 ID 识别，无法确认的同名文件不覆盖。

### 8.2 最小数据合同

- **DailyEntry**：schema、journalId、occurredOn、timeZone、revision、正文位置、所选 sourceRefs、createdAt/updatedAt。普通简记为一个 Markdown body，私人补充不混入默认 AI body。
- **SourceRecord**：provider、scopeId、entityId/occurrenceId、业务日期/时间精度、来源版本依据、locator、选中字段、最小证据、coverage 和隐私选择。
- **PeriodScope**：calendar_week/calendar_month、Asia/Shanghai、from/to、asOf、selectionRevision、选中来源与允许参考的历史报告。
- **ReviewSnapshot**：不可变选中事实、精确范围、覆盖/缺项、代码计算的统计、来源版本依据、隐私确认和模型选择。
- **PeriodReport**：reportId、snapshotId、periodKey、revision、候选/确认状态、正文位置、facts/changes/uncertainties/suggestions、citations、confirmedAt、确认原文保全引用。

首版使用 Node 标准库及现有 DSH/React 能力，不先引入 SQLite、通用事件平台或统一全插件数据库。schema 验证、来源作用域与实体语义必须覆盖未知版本和错误数据。

### 8.3 冲突、失败与历史

1. 保存前比较实际正文与编辑时依据；mtime/size 只可用于缓存提示，不能单独授权覆盖。
2. 保存操作先记录身份、期望版本和受控暂存；文件与状态收据都成功后才显示已保存。文件已落位而状态保存失败，保留 recovery_needed，不假装原子提交。
3. 外改时保留原文件和本地草稿，允许重新载入或另存；未知 schema 保原文并停止相关写入。
4. 候选采用前来源或选择变化，标 stale 并重新预览。已确认报告保留当时快照，后续来源变化不自动改写历史正文。
5. 已确认 Markdown 外改或缺失，明确显示 externally_modified/missing；保全原文可查，恢复须显式选位置且不覆盖新编辑。
6. 卸载/关闭先拒新请求，持久化取消/待恢复状态，等待本次自有写入和模型响应释放；启动后不自动继续模型生成或覆盖文件。
7. 备份包含本插件简记、私人补充、快照、报告全部修订、索引与收据。恢复在新隔离目录和独立重启验证，不把来源插件备份或整个 vault 备份混称已覆盖。

## 9. 新插件 API 与代码职责

以下为拟建接口，路径均位于 `/dsh-review/api`；实现时同步请求/响应、校验、客户端和测试，不以文档表格冒充现有接口。

| API | 主要职责与约束 |
|---|---|
| `GET /health`、`GET/PUT /settings` | 配置记录根、来源能力和模型偏好；不返回凭据 |
| `GET /days?from=&to=`、`GET /days/:date` | 日期列表、简记及引用；未来日期与已存草稿分开 |
| `PUT /days/:date`、`PUT /drafts/:date` | 版本/原文依据校验，正式保存与草稿状态分开 |
| `GET /days/:date/history`、`POST /days/:date/restore` | 查看历史；恢复前保留当前正文且不覆盖外改 |
| `GET /sources?from=&to=` | 汇总四来源的只读事实、覆盖和失败状态 |
| `POST /reviews/preview` | 计算范围、校验选择、展示精确输入并生成待确认快照 |
| `POST /reviews/generate`、`POST /reviews/:id/cancel` | 确认后模型生成与持久取消，进度采用现有 SSE 模式 |
| `GET /reviews`、`GET/PATCH /reviews/:id` | 报告历史、候选编辑和版本校验 |
| `POST /reviews/:id/confirm`、`POST /reviews/:id/restore` | 采用新修订、保全确认原文；恢复先预览再确认 |
| `GET /sources/:ref` | 展示保存证据和当前可用状态；ref 是内部引用 ID，不是任意路径 |

建议模块按职责组织：host 入口与 API；client 页面与导航；日记保存/恢复；四来源适配；日期和确定性统计；回顾快照/报告生命周期；文本模型调用及候选校验。不要把整个新插件塞进文献阅读室的 client.js，也不复制其全部 AI/归档代码。

## 13. 交付与审查结论

首版完成的可见标准：用户能在每日页简单记几句话，看到其他插件已有事实；选择一周或一个月、检查实际发送范围后生成回顾；核对出处、修改建议、确认保存；重开后正文、来源和版本仍正确，且原有插件功能不受影响。

建议首先审查：每日是否足够轻量；周/月模板与行动建议是否实用；来源口径和缺记是否诚实；跨插件跳转是否需要上述最小配套改造。采用后再按 JR-01–JR-09 实施，不把计划书等同于实施授权。

本轮仅文档勘察与计划书编写，没有运行产品测试、启动应用、调用模型、创建自动化或读取私人业务库。当前接口事实为静态证据，性能指标和上述验收矩阵均为未来实施要求。
