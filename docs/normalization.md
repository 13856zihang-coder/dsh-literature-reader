# 仓库规范化与产品边界

## 这次调整的原则

- **本地优先**：PDF 导入、阅读、提问和本地总结不依赖 Obsidian。Obsidian 是总结与笔记的可选同步目标，不是启动前提。
- **配置可移植**：发行补丁不携带开发者电脑的盘符。`obsidianVault` 留空时从 Obsidian 注册表自动发现，`dataDir` 留空时使用系统 `Documents/DSH-Literature`。
- **失败可解释**：未发现 vault 时返回结构化的 `available: false`，界面显示下一步和官方安装入口，不把异常伪装成空库或无限加载。
- **功能分层**：首屏只围绕“导入 → 阅读 → 提问 → 总结”；库管理、笔记整理和自动插图保留在二级入口。

## 横向参考

本轮参考了几个同类项目的公开说明：

- Paper Manager 把核心 PDF 库、搜索和批注保持为本地能力，AI 作为可选能力。
- Local Book Reader 将原文件视为只读输入，阅读进度和研究结果作为普通 Markdown 保存。
- PDF++ 以 Obsidian 原生链接和注释工作流为中心，把能力集中在 PDF 阅读与批注。

因此本插件继续保留 DSH 的 AI 阅读特色，但把 Obsidian 写入降级为可选同步，并让默认配置脱离单机路径。

## 验证边界

仓库测试覆盖主机 API、本地缓存和 vault 同步的临时目录场景。真实 Obsidian 安装、系统注册表发现和实际 DSH 宿主仍需在目标机器上做一次手工验收。
